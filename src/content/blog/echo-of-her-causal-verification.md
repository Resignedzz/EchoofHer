> 今天真正的进展不是把某个指标做漂亮，而是建立了一条判据：一个学习成分要被承认有效，必须能通过"删掉它，输出就变"的检验；如果没变，先怀疑实验设计，再怀疑这个成分。

昨天解决的是"她交付得对不对"，今天解决的是一个更根本的问题：**她学到的经验，到底有没有产生作用？**

此前的学习闭环是开环的：技能复盘出 tip，tip 直接拼进 prompt，没有任何"用了之后是否变好"的验证。同样，调用链里写了"你记得：……"，也没人能回答这段记忆是不是真的影响了回答，还是只是一段装饰性的上下文。

今天围绕 tips 与 memory 做了两件事：先把归因链闭合，再用干预重放做因果验收。过程中最有价值的部分，不是最后拿到的好数字，而是**第一次跑出来的"0/3"后来被证明是无效实验**。

## 一、起点：tips 只进不出

原来的 `skill_tips` 只有一段文本和一个成功率，回答不了三个问题：

1. 这一轮到底注入了几条 tip？
2. 注入之后这次执行是成功还是失败？
3. 同一条 tip 在合并、改写之后，之前的效果数据还能不能算在它头上？

所以先补了三样东西：

- `skill_tips` 增加 `adopted_count` / `success_after_adopt` / `version`；
- 注入时把"本轮用了哪几条"写进 `tip_events`，失败可以回查具体 tip；
- 新增 `tip_ab_test`，用对照组和实验组做真实双进程消融。

归因链闭合后，才谈得上"这条经验有用没用"。

## 二、两轮小流量对照：没有看到分数增益

P2.3 用真实请求跑了两轮有/无 tips 的对照，累计 28 轮有效样本。

结果是：**没有观察到分数增益。**

这不算失败。相反，它说明此前"tip 越多、回答越好"的假设从来没有被验证过，只是被默认了。既然对照没给出正向信号，就不应该继续让 tips 自由增长，更不应该根据几轮结果自动晋升新 tip。

## 三、先收敛，再验证：把三件同类经验合成一条

P2.5 做的是内容层面的收敛，而不是按"连续两轮零增益"机械淘汰：

- #21（coder 必须给完整可运行代码）退役：它描述的交付问题已经由最终回复补全机制确定性处理，再注入只是重复；
- #22 与 #23 讲的是同一件事——关键论断只能用本轮实际检索到的资料和引用编号，并保留可定位 URL。两条合并为新的 #22，`evidence_count=2`、`confidence=0.9`，旧 #23 退役；
- 单技能注入上限设为 3 条，防止 prompt 被经验文本撑爆。

当时全量测试 110 passed。这里有个容易踩的坑：**合并前 #22 的旧 8 次注入与结果，不能再算作合并后新文案的效果证据。**

## 四、M2 因果验收：50 条轨迹里 19 条真的被"想过"

P1 的实现会让每一轮对话保存 `thought_trace`，于是可以做一件比"读日志"强得多的事：把中间结论换掉，看最终输出会不会变。

M2 对 50 条真实轨迹做了离线温度 0 重放，每条包含 1 次干预和 2 次不变对照：

- 19 / 50 条出现因果关系（38%）；
- 对照组 50 / 50 稳定，说明重放本身是可靠的；
- 分成分看：参考资料 10 / 38、关系段 9 / 11、偏好段 0 / 1。

结论很克制：**中间结论不是全 0 装饰，但也不是每一步都有因果力。** 参考资料和关系段的注入确实会改变输出，偏好段样本太少，还不能下结论。

## 五、M2b 的记忆消融：那个 0/3 是假的

memory 的单成分干预很简单：只删掉 system prompt 里的 `你记得：……` 这一段，其它什么都不动。

第一轮挑了 3 条真实对话，删除记忆后输出**全部没有变化**，报告写出来是 0/3。如果就此收工，结论会是"记忆注入是装饰性的"。

但这个结论是错的。原因是历史消息里早就带着事实：

- 首轮用户说过"我叫林舟，在深圳做硬件工程"；
- 之后多轮闲聊，她的回复自然复述了"徒步""摄影"；
- 最近 10 条历史里仍然留着这些内容，system 里删不删 `你记得：` 都一样。

更隐蔽的一层在滚动摘要：会话消息累计到阈值后会自动生成摘要，摘要里同样带着事实，而且不在 `你记得：` 这一行。只检查那一行是否消失，会漏掉它。

于是重新采样，这次三个新会话（许川/南京/建筑设计、苏晴/厦门/海洋生物、陆远/西安/博物馆策展）都满足两个条件：

1. 用唯一措辞的隔离轮次把原始事实和含事实的回复全部刷出最近历史；
2. 控制在摘要阈值以下，不触发滚动摘要。

最终三条样本的 system 有记忆注入、历史无事实、其它 system 段也无事实。重放结果：

| 样本 | 移除后是否有变化 | 对照是否稳定 |
|---|---|---|
| 许川（南京 / 建筑设计） | 是 | 是 |
| 苏晴（厦门 / 海洋生物） | 是 | 是 |
| 陆远（西安 / 博物馆） | 是 | 是 |

**3 / 3 因果，3 / 3 对照稳定。** 文本差异也明显：移除记忆后的发散度是 0.821 / 0.796 / 0.909，而两次不变对照只有 0.257 / 0.075 / 0.631。

需要写清楚的是：这三条用的是虚拟人物资料，但 facts 是经过真实 `/api/chat` 和后台提取链路生成的，不是手工 INSERT。它属于**受控样本**，不能冒充自然用户数据，也不能外推到 persona。

## 六、合并后的 #22：分组有效，但没有总体增益

tips 的注入发生在技能内部，不在最终 system snapshot 里，所以只能继续用双进程消融：

- treatment：`ECHO_LEARNING_TIPS=1`，跑 17580；
- control：`ECHO_LEARNING_TIPS=0`，跑 17581。

本轮只测 researcher 的两个案例（`research-sort`、`research-cache`），2 案例 × 2 次 × 2 臂，共 8 个请求。分组检查全部通过：8 条都路由到 researcher，`invalid_routing` 与 `invalid_assignment` 均为空，treatment 只注入了 #22，control 一条都没注入。

| 指标 | control | treatment |
|---|---:|---:|
| 有效轮次 | 4 | 4 |
| pass | 2 / 4 | 2 / 4 |
| 平均分 | 0.700 | 0.675 |
| 平均首字秒数 | 4.945 | 4.879 |

配对差是 +0.10 / 0.00（research-sort）和 −0.10 / −0.10（research-cache）。

`research-cache` 两臂都没能检索到 MDN 官方页面，低分主因是检索召回不足和必要来源缺失——**提示词没法凭空补出不存在的来源**。所以本轮既不能证明 #22 有增益，也不足以证明它有害，更不能据此自动晋升或退休。

## 七、今天得到的几个经验

**无效实验比错误结论更危险。** 0/3 那次跑得很顺，报告格式也对，唯一的问题是它测的不是 memory。实验设计里最贵的错误，是混杂因素没被排除。

**"只删那一段"不等于单变量。** 历史消息、滚动摘要、用户原始陈述都可能是同一个信息的副本。做消融要先把副本清干净，否则改什么都没用。

**对照稳定和因果显著是两件事。** 两个不变对照稳定，只说明重放本身可靠；只有移除成分后输出改变，才算因果。两者都满足才能下结论。

**没增益不等于有害。** 8 个请求、4 个配对，能说明"本轮看不到方向"，不能说明 tip 应该退役。小样本的正确用法是排除明显错误，而不是做晋升决策。

**测试流量必须能被识别。** 本轮 memory 用的 `m2b-` 前缀不在技能反思的测试前缀里，好在这些是直接对话、没有技能路由，才没有污染 tip 数据。后续 tips 批次统一改用 `m2-` / `p2-live-`。

下一步优先解决 `research-cache` 的官方页面召回，再评估 #22 能否改善最终转述；persona 需要等真实的导入数据，不用默认关系段凑数。

如果只能从今天带走一句话，那就是：**别相信"我加了它，所以它有用"；要相信"我删了它，输出变了"。**
